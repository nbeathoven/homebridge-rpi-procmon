## Requirements and Acceptance

PASS means supported by the supplied automated or operational evidence, not
physical Apple Home UI verification. Compatibility retains the read-only 0.3.0
API model; live integration was verified against deployed 0.3.1. Preexisting
bugs are not compatibility requirements.

| ID | Accepted requirement | Result |

## Accepted Limitations and Follow-Up

- Replay/producer-epoch handling is deferred under the trusted-LAN current-read
  model. Architect reports no source blockers; no replay-protection guarantee is
  made.
- No independent freshness timer: bounded request abort and polling are accepted.
  Availability changes follow that cadence, not an exact threshold-expiry timer.
- Physical Apple Home/UI behavior is unverified. Automated HAP/state and live API
  results must not be described as physical UI verification.
- Only Node 22.21.1 and 24.22.1 evidence is claimed, not every advertised runtime
  or Homebridge version.
- Second scheduled poll passed October 22, 00:01:28 EDT. Cache modification time
  advanced to `2026-10-22T04:01:28.373Z`, all six completion timestamps advanced,
  all seven sensors remained closed/active/no-fault, and all seven UUIDs were
  unchanged. Child PID 14202 and other plugin PIDs remained stable. Homebridge
  and procmon were active with `NRestarts=0`; procmon reported six healthy monitors.
- Plugin main CI for `b9c5750` passed in run `39719765648`; upstream procmon CI
  also passed. Parent maintains the separate `docs/DEPLOYMENT-0.1.4.md` record
  and will append second-poll/final verification fields; this PM did not edit it.
